# SOURCES.md — 문서의 출처와 컷오버 대장

> 이 문서가 답하는 것: **어떤 문서를 무엇으로부터 어떻게 채우는가.**
> 출처의 종류가 정해지면 채우는 방식도 정해진다.

- 상태: 기안
- 기안일: 2026-08-31

## 정본의 원칙

진실의 종류마다 정본이 하나씩 있다. 같은 사실을 두 곳에 쓰지 않는다.

| 진실의 종류 | 정본 |
|---|---|
| 요건·규칙·판단의 근거 | 리포의 md |
| 개념과 컴포넌트의 **이름** | **용어집**(지금부터) |
| 디자인 시스템의 토큰·컴포넌트 | **Claude Design → 컷오버 후 리포** |
| 비주얼(배치·크기·간격) | Figma → Claude Design 화면 프로토타입 → `template/` → Storybook |
| 구현 | Storybook |

**매체로 가르지 않고 층으로 가른다.** Figma의 와이어 프레임 하나에서 두 가지가 나온다 — 붙어 있는 주석·조건문은 md로 옮기고, 배치는 옮기지 않는다.

## 컷오버 — 언제 리포가 정본이 되는가

**Claude Design 재개 작업의 「6. repo 적재」 시점이다.**

| 시점 | 디자인 시스템의 SSoT |
|---|---|
| 지금 ~ 재개작업 5번(화면 프로토타입 ＋ UI 스펙) | **Claude Design** |
| 재개작업 6번(repo 적재) 이후 | **리포** (`packages/design-system`) |

재개작업 1~5번이 전부 Claude Design에서 일어난다. 그 전에 리포를 정본으로 선언하면 아무도 고치지 않는 정본이 생긴다.

### 예외 — 이름은 지금부터 용어집이 정본이다

재개작업 2번(컴포넌트 고아 분석)에서 새 컴포넌트가 다수 나온다. 거기서 이름을 지으면 용어집은 뒤따라 적는 기록이 된다.

| 판정 조건 | 아크션 |
|---|---|
| 새 컴포넌트·개념의 이름을 짓는다 | **용어집에 행을 먼저 추가한다.** 그 다음 Claude Design에서 그 이름을 쓴다 |
| 이미 있는 컴포넌트 41개의 이름 | S10에서 용어집으로 옮긴다 |
| 이름이 아니라 값·구조를 바꾼다 | 컷오버 전이므로 Claude Design에서 한다 |

## 출처의 6종류

| 종류 | 다루는 방식 |
|---|---|
| **Figma · 텍스트** | 발췌하고 재구성한다. 옮긴 시점부터 md가 정본이며 Figma 쪽 텍스트는 갱신하지 않는다 |
| **Figma · 비주얼** | **리포에 직접 들어오지 않는다.** Claude Design 화면 프로토타입의 입력이 된다. **프레임에 붙은 주석·조건문은 「Figma · 텍스트」로 다룬다** |
| **Claude Design · 산출물** | 토큰은 **무손실 복사**한다. 컴포넌트는 **소스 이식**한다. **화면 프로토타입은 `template/` 으로 export한다**(정확도 B+). 아래 표 참조 |
| **Claude Design · 경위** | 대화·핸드오프 팩. **규칙의 근거**를 여기서 딴다. 규칙 자체는 산출물이 정본이다 |
| **사람의 결정** | 그 자리에서 쓴다. 정하면 그것이 정본이다 |
| **작업 중 발견** | 발생할 때 한 행씩 넣는다 |
| **기계 생성** | 실행 결과를 커밋한다. 손으로 고치지 않는다 |

### Claude Design 산출물 — 무엇을 어떻게 옮기는가

컴포넌트는 표준 React ＋ CSS 변수 참조이며 외부 의존성이 0이다. 그래서 **「보고 재구현」이 아니라 「소스 이식」**이다.

| 대상 | 방식 |
|---|---|
| `tokens/*.css` · `globals.css` | **무손실 복사한다.** 다시 쓰지 않는다 |
| 컴포넌트 `.jsx` | **소스 이식한다.** 인라인 style → className 변환은 선택 사항이다 |
| 컴포넌트·요소의 **명칭** | 그대로 가져온다. 용어집 English 열과 `DS-update-list` 의 입력이다 |
| 원칙·의도(`guidelines/*.html`) | `DESIGN.md` 로 옮긴다. **규칙만 쓰고 실측값은 쓰지 않는다** |
| 화면 HTML(`TOP.html`) | **`template/` 으로 export한다**(핸드오프 6단위 ⑤·정확도 B+). 시각적 참조이며 CSS 를 React 구현으로 옮기지 않는다 |
| 컴포넌트 사양 | **Storybook stories 로 만든다.** `.prompt.md` 는 생성 규칙이라 검증 정답지와 다르다 |

### Claude Design 경위 — 근거를 여기서 딴다

DESIGN-CHARTER 원칙 8은 모든 규칙에 근거를 한 줄 붙이라고 요구한다. 산출물에는 결과만 있고 근거가 없다.

| 판정 조건 | 아크션 |
|---|---|
| 대화 안에서 **번복된 판단**이 있다 | **마지막 것만 유효하다.** 중간 발언을 규칙으로 쓰지 않는다 |
| 대화의 서술이 산출물과 다르다 | **산출물이 맞다.** 대화는 경위이지 결과가 아니다 |
| 대화에 있는 내용을 옮긴다 | **규칙으로 승격할 것만** 고른다 |

### 반입 방법

**통째로 던져넣되 커밋하지 않는다.**

| 판정 조건 | 아크션 |
|---|---|
| Claude Design의 산출물·경위를 Claude에게 읽힌다 | `design/_import/` 에 둔다. 이 경로는 `.gitignore` 에 넣는다 |
| 부분만 발췌해서 읽힌다 | **하지 않는다.** 명칭과 구조가 빠지고, 번복 관계가 안 보인다 |
| 반입한 사실을 기록한다 | 아래 「컷오버 기록」에 **export 일시와 출처의 식별(계정·파일명)**을 적는다. 공개 공유 링크는 조직 이동으로 깨지므로 적지 않는다(ADR-0002) |

파일이 리포에 남으면 나중에 거기서 값을 복사한다. 「참조하지 말라」고 써도 파일이 있으면 읽힌다.

## 제품의 전제

문서를 쓸 때 전부 걸리는 사실이다.

| 사실 | 어디에 걸리는가 |
|---|---|
| **한/일 이중언어(i18n)** | UI-SPEC 을 쓸 때 문구를 직접 쓰지 않고 **키 기반**으로 짠다. UX 라이팅의 범위가 2개국어다 |
| 해외 커리어 B2C 멘토링 | `PRODUCT.md` 의 첫 줄 |
| 라이트 단일 테마 | `DESIGN.md`. 다크 대응을 전제하지 않는다 |
| 리포에 앱이 없다 | 디자인 시스템의 자리는 `packages/design-system` 이다 |
| **컴포넌트의 형태가 미정이다** | S6에서 정한다. 변환하면 이식 정확도가 A−에서 B+로 떨어진다 |

### 연결 규칙

| 판정 조건 | 아크션 |
|---|---|
| UX 라이팅이 **개념의 호칭 자체**를 바꾼다 | **용어집 행을 함께 고친다.** English 식별자를 바꿀지도 같이 판단한다 |
| UX 라이팅이 **문구**를 바꾼다(버튼 라벨 · 에러 메시지 · 안내문) | 용어집과 무관하다 |

판정 기준은 **「이것이 개념의 이름인가, 그 개념에 대해 하는 말인가」** 다.

## 사람의 결정 — 언제 멈추고 묻는가

「불명·애매하면 질문한다」로는 작동하지 않는다. **AI 는 자기가 애매한지를 모른다.** 그래서 판정 조건을 쓴다.

**판정 조건 4행의 정본은 [CLAUDE.md](../CLAUDE.md) 「일하는 방식」이다.** 매 세션이 CLAUDE.md 를 읽으므로 표는 거기에 둔다. 여기에 복제하지 않는다.

표의 **3·4행이 1·2행만큼 중요하다.** 전부 물으면 안 묻는 것과 같이 나쁘다.

### 물을 때의 형식

1. **선택지** — A~E 로 고를 수 있는 형태
2. **추천 1개와 이유**
3. **이것을 정하지 않으면 무엇이 막히는가**

3번이 있으면 사람이 「지금 답할지, 가정을 세우고 진행시킬지」를 판단할 수 있다.
