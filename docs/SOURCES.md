# SOURCES.md — 문서의 출처와 반입 대장

> 이 문서가 답하는 것: **어떤 문서를 무엇으로부터 어떻게 채우는가.**
> 출처의 종류가 정해지면 채우는 방식도 정해진다.

- 상태: 기안
- 기안일: 2026-08-31

## 정본의 원칙

진실의 종류마다 정본이 하나씩 있다. 같은 사실을 두 곳에 쓰지 않는다.

| 진실의 종류 | 정본 |
|---|---|
| 요건·규칙·판단의 근거 | 리포의 md |
| 개념과 컴포넌트의 **이름** | **용어집** |
| 디자인 시스템의 토큰·컴포넌트 | **아래 「정본의 두 축」** |
| 비주얼(배치·크기·간격) | Figma → Claude Design 화면 프로토타입 → `template/` |
| 구현 | **이 리포 밖**(엔지니어) |

### 정본의 두 축 — 고치는 곳과 읽는 곳

디자인 시스템만 축이 둘이다. **물음이 둘이라 답도 둘이다.**

| 물음 | 이름 | 어디 |
|---|---|---|
| 값을 **바꾸려면** 어디로 가나 | **편집의 정본** | **Claude Design** |
| 값을 **알려면** 어디를 보나 | **참조의 정본** | **[`design/ds-export/`](../design/ds-export/SOURCE.md)** |

| 판정 조건 | 아크션 |
|---|---|
| 토큰 값·컴포넌트 구조를 바꾼다 | **Claude Design 에서 한다.** 리포에서 고치지 않는다 |
| 값이 무엇인지 알고 싶다 | **`ds-export/` 를 본다.** Claude Design 을 열지 않는다 |
| `ds-export/` 와 Claude Design 이 다르다 | **Claude Design 이 맞다.** 재export 해서 `ds-export/` 를 통째로 교체한다 |
| `ds-export/` 를 손으로 고치고 싶다 | **고치지 않는다.** 고치면 두 축이 갈린다 |

**이 두 이름을 다른 문서에서 다시 정의하지 않는다.** 여기를 가리킨다.

**매체로 가르지 않고 층으로 가른다.** Figma의 와이어 프레임 하나에서 두 가지가 나온다 — 붙어 있는 주석·조건문은 md로 옮기고, 배치는 옮기지 않는다.

## 컷오버 — 없다

**이 리포는 디자인 시스템을 구현하지 않는다**([ADR-0005](adr/0005-design-team-deliverables.md)). 리포가 디자인 시스템의 정본이 되는 시점이 오지 않는다.

| 무엇 | 편집의 정본 | 참조의 정본 |
|---|---|---|
| 토큰·컴포넌트·원칙 | **Claude Design** | **`design/ds-export/`** — 인계 산출물이기도 하다 |
| 화면의 사양 | **리포** (`UI-SPEC.md`) | 같음. 축이 하나다 |
| 화면의 비주얼 | **리포** (`template/`) | 같음. 축이 하나다 |

**축이 둘인 것은 디자인 시스템뿐이다.** 위 「정본의 두 축」이 정본이다.

### 예외 — 이름은 용어집이 정본이다

컴포넌트 고아 분석에서 새 컴포넌트가 다수 나온다. 거기서 이름을 지으면 용어집은 뒤따라 적는 기록이 된다.

| 판정 조건 | 아크션 |
|---|---|
| 새 컴포넌트·개념의 이름을 짓는다 | **용어집에 행을 먼저 추가한다.** 그 다음 Claude Design에서 그 이름을 쓴다 |
| 이미 있는 컴포넌트 41개의 이름 | S10에서 용어집으로 옮긴다 |
| 이름이 아니라 값·구조를 바꾼다 | **Claude Design에서 한다.** 리포에서 고치지 않는다 |

## 출처의 6종류

| 종류 | 다루는 방식 |
|---|---|
| **Figma · 텍스트** | 발췌하고 재구성한다. 옮긴 시점부터 md가 정본이며 Figma 쪽 텍스트는 갱신하지 않는다 |
| **Figma · 비주얼** | **리포에 직접 들어오지 않는다.** Claude Design 화면 프로토타입의 입력이 된다. **프레임에 붙은 주석·조건문은 「Figma · 텍스트」로 다룬다** |
| **Claude Design · 산출물** | 토큰은 **무손실 복사**한다. 컴포넌트는 **소스 이식**한다. **화면 프로토타입은 `template/` 으로 export한다**(정확도 B+). 아래 표 참조 |
| **Claude Design · 경위** | 대화·핸드오프 팩. **규칙의 근거**를 여기서 딴다. 규칙 자체는 산출물이 정본이다 |
| **사람의 결정** | 그 자리에서 쓴다. 정하면 그것이 정본이다 |
| **작업 중 발견** | 발생할 때 한 행씩 넣는다 |
| **기계 생성** | 실행 결과를 커밋한다. 손으로 고치지 않는다 |

### Figma · 텍스트 — 읽는 방법

**페이지 전체를 한 번에 가져오지 않는다.** `Wireframe` 한 페이지가 5,008,830 bytes 다.

| 판정 조건 | 아크션 |
|---|---|
| 플로우의 텍스트를 읽는다 | **이름 붙은 덩어리 단위로 node id 를 지정해 읽는다.** 한 덩어리를 끝내고 md 로 써둔 뒤 다음으로 간다 |
| 중간 결과가 쌓인다 | **컨텍스트에 쌓지 않는다.** md 에 쓰고 버린다 |
| 읽기용 정리 페이지를 Figma 에 만들었다 | 그것은 **작업대이지 정본이 아니다.** md 로 옮긴 뒤에는 유지보수하지 않는다 |

정리 페이지를 유지하면 **정본이 셋이 된다** — 원본 와이어 · 정리 페이지 · md.

### 주석과 화면을 둘 다 읽는다

**주석만 읽고 화면 사양을 쓰지 않는다.** 주석은 **예외와 조건**을 적는 곳이고 **무엇이 놓여 있는가는 화면에만 있다.**

| 판정 조건 | 아크션 |
|---|---|
| 화면의 `UI-SPEC` §4·§6 을 쓴다 | **주석과 화면 프레임을 둘 다 연다.** 주석만으로 블록을 세지 않는다 |
| 주석에 없는 요소가 화면에 있다 | **화면에 있는 것이 사실이다.** 빠뜨리지 않는다 |
| 화면에 없는 규칙이 주석에 있다 | **주석이 사실이다.** 주석은 조건과 거동을 적는다 |

**2026-09-14 에 이것을 안 지켜서 `qna-detail` 에서 어긋남이 9건 나왔다.** 주석 20건만 텍스트로 뽑고 화면은 `qna-feed` 1장만 열었다. 제목 앞의 `Q.`, 액션의 가운데 정렬, 맨 아래 「인기 태그」 섹션은 **전부 주석에 없고 화면에만 있었다.**

### 어긋났을 때 — 한쪽을 버리지 않는다

**와이어·주석·디자인 시스템이 서로 어긋난다.** 어느 하나를 「정본」으로 세워 나머지를 버리면 판단이 빨라지는 대신 **틀린 채로 멀리 간다.**

| 판정 조건 | 아크션 |
|---|---|
| 와이어와 디자인 시스템이 어긋난다 | **멈추고 디자이너에게 묻는다.** 어느 쪽이 이기는지는 사안마다 다르다 |
| 주석과 화면이 어긋난다 | **멈추고 묻는다** |
| 와이어가 틀렸다고 판단했다 | **혼자 버리지 않는다.** 그렇게 본 근거를 붙여 묻는다 |
| 물을 것이 쌓여 진도가 안 나간다 | **한 번에 모아 묻는다.** 건마다 멈추지 않는다 |

**「무조건 피그마가 정본」도 「무조건 디자인 시스템이 정본」도 아니다.**

- 디자인 시스템은 **최소 품질과 일관성의 바탕**이다. 화면마다 다시 정하지 않기 위해 있다
- 와이어는 **무엇을 만들 것인가**다. 디자인 시스템에 없으면 **디자인 시스템을 고친다**
- **와이어가 틀리는 일도 있다.** `qna-detail` 의 답변별 스크랩이 그것이다 — 와이어는 버튼을 답변마다 두지만 스크랩의 단위가 질문이라 한 질문에 여러 개가 동시에 켜진다. **디자이너가 와이어 오류로 판정했다**(2026-09-14)

`[review]`
**근거**: 한쪽을 버리면 **버린 쪽에 있던 정보가 영영 안 돌아온다.** 물어서 정한 것은 기록에 남고 다음 화면에서 재사용된다.

### Claude Design 산출물 — 무엇을 어디에 두는가

컴포넌트는 표준 React ＋ CSS 변수 참조이며 외부 의존성이 0이다. **이 리포는 이식하지 않고 그대로 보관한다.** 이식은 엔지니어의 일이다.

| 대상 | 어디에 |
|---|---|
| `tokens/*.css` · `styles.css` | `ds-export/project/tokens/` — **무손실 복사.** 값을 읽을 곳이다 |
| 컴포넌트 `.jsx` · `.d.ts` · `.card.html` | `ds-export/project/components/` — **무손실 복사** |
| 컴포넌트·요소의 **명칭** | 용어집 English 열과 `DS-update-list` 의 입력이다 |
| 원칙·의도(`guidelines/*.html`) | `ds-export/project/guidelines/`. **규칙만 골라 `DESIGN.md` 로 옮긴다**(실측값은 쓰지 않는다) |
| 화면 HTML | **`design/screens/<id>/template/` 으로 export한다.** 정적 HTML/CSS 4파일, JS 없음 |
| 미구현·미정 | `DS-update-list.md` 의 `DS-nn` |

**사본을 손으로 고치지 않는다.** 고치면 Claude Design 과 갈리고, 어느 쪽이 맞는지 판정할 수 없다.

#### 외부 라이브러리를 쓰기로 한 부품

**`ds-export/` 에 외부 의존성을 넣지 않는다.** 라이브러리를 쓰기로 정했어도 **사양으로 지정할 뿐 import 하지 않는다.**

| 판정 조건 | 아크션 |
|---|---|
| 그 부품을 라이브러리로 구현하기로 정했다 | **`prompt.md` 첫머리에 「구현은 ○○를 쓴다」를 적는다.** 이름·라이선스·런타임 의존을 함께 적는다 |
| `.jsx` 를 만든다 | **그 라이브러리를 import 하지 않는다.** 표준 React 로 모양과 거동만 낸다. 그것은 **시각과 거동의 참조**이지 이식원이 아니다 |
| 그 부품에 우리 쪽 규칙이 있다 | **`prompt.md` 가 갖는다** — 토큰·치수·타이밍·상태. 라이브러리의 기본값을 그대로 두지 않는다 |
| 라이브러리를 새로 고른다 | **사람의 승인을 받는다**([CLAUDE.md](../CLAUDE.md) 「보안」). 이유와 **라이선스**를 붙인다 |

**두 가지 이유다.** ① **Claude Design 은 패키지를 설치하지 못한다.** 편집의 정본이 거기이므로 물리적으로 막힌다. ② **라이브러리 선택은 엔지니어의 층이다** — 「컴포넌트의 형태는 엔지니어가 정한다」와 같은 선이다. 우리는 **무엇을 쓸지 지정**하고 **어떻게 붙일지는 넘긴다.**

##### 그래도 부품을 만드는가 — 이것이 갈린다

**위의 표는 「부품을 만든다」를 전제한다. 안 만드는 쪽도 있다.**

| 판정 조건 | 아크션 |
|---|---|
| 우리가 정할 것이 **모양과 거동**이고 라이브러리는 그것을 실어 나른다 | **DS 에 부품을 만든다.** 위 표대로 `prompt.md` 에 라이브러리를 지정한다 |
| 라이브러리가 **UI 와 상태 기계를 통째로 갖고**, 우리가 정할 것은 **어디에 놓는가와 어떤 기능을 켜는가**뿐이다 | **DS 에 부품을 만들지 않는다.** 사양은 그 화면의 `UI-SPEC.md` 가 갖고 `DS-nn` 은 **각하**한다 |
| 어느 쪽인지 모르겠다 | **`prompt.md` 에 쓸 우리 쪽 규칙을 세어 본다.** 토큰·치수·타이밍·상태가 나오면 앞쪽, 「기능 on/off」만 나오면 뒤쪽이다 |

**앞쪽의 사례가 `Toast` 다**(`DS-09`) — 와이어가 `Sonner` 를 쓰고 구현도 그것으로 간다(2026-09-12). 그런데 **체류 시간·hover 정지·액션 수가 종류를 정한다**가 전부 우리 규칙이다. 그래서 부품을 만들고 `sonner` 는 사양으로만 적는다.

**뒤쪽의 사례가 `RichTextEditor` 다**(`DS-15` · 2026-09-12 각하). **blocknote 가 툴바·블록·단축키·직렬화를 통째로 갖는다.** 우리가 정할 것은 **어느 기능을 켜는가**(볼드·링크·이미지…)와 **1000자 카운터**뿐이고, 그것은 화면의 사양이다. **Claude Design 에 껍데기를 만들면 실물과 안 닮은 것이 하나 더 생긴다.**

**각하해도 이름은 용어집에 남는다.** 화면 UI-SPEC 이 그 이름으로 부른다.

### Claude Design 경위 — 근거를 여기서 딴다

DESIGN-CHARTER 원칙 8은 모든 규칙에 근거를 한 줄 붙이라고 요구한다. 산출물에는 결과만 있고 근거가 없다.

| 판정 조건 | 아크션 |
|---|---|
| 대화 안에서 **번복된 판단**이 있다 | **마지막 것만 유효하다.** 중간 발언을 규칙으로 쓰지 않는다 |
| 대화의 서술이 산출물과 다르다 | **산출물이 맞다.** 대화는 경위이지 결과가 아니다 |
| 대화에 있는 내용을 옮긴다 | **규칙으로 승격할 것만** 고른다 |

### 반입 방법 — 자리가 둘이다

**사양은 커밋하고, 경위는 커밋하지 않는다.**

| 무엇 | 어디에 | 커밋 |
|---|---|---|
| **사양** — 토큰·컴포넌트·원칙·자산 | `design/ds-export/` | **한다.** 인계 산출물이다([ADR-0005](adr/0005-design-team-deliverables.md)) |
| **경위** — 대화·재개 팩·이관 메모 | `design/_import/` | **하지 않는다.** `.gitignore` 에 있다 |

| 판정 조건 | 아크션 |
|---|---|
| 부분만 발췌해서 반입한다 | **하지 않는다.** 명칭과 구조가 빠지고, 번복 관계가 안 보인다 |
| 용량이 큰 것이 섞여 있다 | 폰트 바이너리·중복 사본·데모는 뺀다. **뺀 것을 `ds-export/SOURCE.md` 에 적는다** |
| 반입한 사실을 기록한다 | 아래 「컷오버 기록」에 **export 일시와 출처의 식별(계정·파일명)**을 적는다. 공개 공유 링크는 조직 이동으로 깨지므로 적지 않는다(ADR-0002) |

경위를 커밋하지 않는 이유는 **정본이 셋이 되는 것을 막기 위해서**다. 대화 기록이 리포에 남으면 거기서 규칙을 딴다.

#### SHA 운용

**원본 zip 의 SHA-256 을 남긴다.** 적는 곳은 `ds-export/SOURCE.md` 이고, 아래 「반입 기록」에도 같은 값을 적는다.

**SHA 는 「어느 시점 사본인가」를 고정할 뿐 「지금도 같은가」는 알려주지 않는다.**

| 판정 조건 | 아크션 |
|---|---|
| 재export 했다. SHA 가 같다 | **아무것도 하지 않는다** |
| 재export 했다. SHA 가 다르다 | `ds-export/` 를 **통째로 교체하고** SHA 를 갱신한다. 같은 PR 에서 용어집·`DS-update-list` 를 맞춘다 |
| 로컬 사본이 Claude Design 보다 낡았다 | **정상이다.** Claude Design 이 정본이다 |

## 제품의 전제

문서를 쓸 때 전부 걸리는 사실이다.

**값의 정본은 [PRODUCT.md](PRODUCT.md) 「제품의 전제」다.** 여기에는 **어디에 걸리는가**만 쓴다.

| 사실 | 어디에 걸리는가 |
|---|---|

## 사람의 결정 — 언제 멈추고 묻는가

「불명·애매하면 질문한다」로는 작동하지 않는다. **AI 는 자기가 애매한지를 모른다.** 그래서 판정 조건을 쓴다.

**판정 조건 4행의 정본은 [CLAUDE.md](../CLAUDE.md) 「일하는 방식」이다.** 매 세션이 CLAUDE.md 를 읽으므로 표는 거기에 둔다. 여기에 복제하지 않는다.

표의 **3·4행이 1·2행만큼 중요하다.** 전부 물으면 안 묻는 것과 같이 나쁘다.

### 물을 때의 형식

1. **선택지** — A~E 로 고를 수 있는 형태
2. **추천 1개와 이유**
3. **이것을 정하지 않으면 무엇이 막히는가**

3번이 있으면 사람이 「지금 답할지, 가정을 세우고 진행시킬지」를 판단할 수 있다.
