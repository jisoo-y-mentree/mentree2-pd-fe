# ADR-0003: 디자인 시스템을 `packages/design-system` 에 커스터마이즈 형태로 둔다

- 상태: 승인
- 날짜: 2026-08-31

## 문맥

shadcn/ui 프리셋 위에 커스텀을 넓게 얹었다. 컴포넌트는 순수 React ＋ 인라인 style ＋ 토큰 참조이며 외부 의존성이 0이다.

리포에 둘 자리와 형태를 정해야 한다. 파이프라인 문서는 `components/ui`를 적었으나 **이 리포에는 앱이 없다.**

## 결정

**`packages/design-system` 에 둔다.**

바닐라 shadcn 위에 오버라이드 폴더를 얹는 방식을 쓰지 않는다. **커스터마이즈한 것 자체를 SSoT로 둔다.**

파이프라인 문서의 `components/ui` 는 이 결정으로 대체된다.

## 근거

- 이 리포는 디자인 산출물과 디자인 시스템을 소유하고 **앱을 소유하지 않는다.** `components/ui` 는 앱 안의 자리이므로 둘 곳이 없다.
- 패키지 형태여야 **앱 리포에서 소비할 수 있다.** 디자인과 앱이 다른 리포에 있는 구성에서 이것이 유일한 경로다.
- 커스텀 폭이 넓다. 오버라이드 방식이면 원본과 오버라이드를 둘 다 읽어야 무엇이 적용되는지 알 수 있다.
- 채택하지 않은 안: **앱 리포로 옮긴다.** 디자인이 소유하는 산출물이 앱 리포에 갇히고, 디자이너가 리포를 오갈 근거가 사라진다.

## 귀결

- 앱 리포는 `@mentree/design-system` 을 의존으로 소비한다.
- **소비 방식이 미정이다** — npm 배포 / 워크스페이스 / 서브모듈 중 무엇인지 정하지 않았다. 앱 리포의 위치와 함께 정한다. 이 미결은 `docs/PRODUCT.md` 「미결」 절에 둔다.
- 되돌리려면 패키지 경계와 소비 측 import를 전부 고쳐야 한다.
