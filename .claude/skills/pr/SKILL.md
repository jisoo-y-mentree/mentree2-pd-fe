# PR 본문의 작성·갱신

본문에 **무엇을 쓰는가**의 정본은 [PR 템플릿](../../../.github/pull_request_template.md)이다. 각 절의 HTML 코멘트가 기입 지시다. 이 스킬은 템플릿에 없는 **작성·갱신의 손순서**만 갖고, 기입 지시를 베끼지 않는다.

이 스킬을 통하지 않고 PR 본문·제목을 쓰는 호출은 [guard-pr.sh](../../hooks/guard-pr.sh) 가 막는다. 서브에이전트로 쓴다면 서브에이전트 자신이 통과시킨다.

같은 훅이 **PR 작성과 동시의 리뷰어 설정**도 막는다(손순서 2.5). 이쪽은 스킬을 통해도 풀리지 않는다.

## 손순서 1: 쓰기 전에 템플릿을 읽고 제목을 정한다

절 구성과 각 절의 코멘트를 읽는다. **제목·본문·코멘트는 한국어로 쓴다**(정본은 [CLAUDE.md](../../../CLAUDE.md) 「Git」).

| 판정 조건 | 제목 |
|---|---|
| 화면 작업의 PR | `<screen-id>: <무엇을 했는가>` |
| 디자인 시스템의 PR | `DS-nn: <무엇을 했는가>` (복수면 `DS-nn·nn`) |
| 그 밖 | prefix 없이 「무엇을 했는가」를 쓴다 |

## 손순서 2: 절마다 코멘트에 맞춰본다

| 판정 조건 | 아크션 |
|---|---|
| 기입 지시에 어긋나는 기술이 있다 | 올리기 전에 고친다 |
| 쓸 것이 없는 절이 있다 | 절째로 지운다 |
| 템플릿에 없는 절을 넣고 싶다 | 넣지 않는다. 절이 필요하면 템플릿의 개정으로 제안한다 |
| 기존 PR의 내용이 바뀌었다 | 본문에 덧붙여 쌓지 않는다. **본문과 제목을 현 상태에 맞춰 다시 쓴다**. 본문은 경위의 이력이 아니라 현재 PR의 설명이다 |

## 손순서 2.5: 작성 호출에 `reviewers` 를 넘기지 않는다

PR은 Draft로 만들고, 기표자 리뷰를 통과시킨 뒤 Ready로 한다. 리뷰어 설정은 그 마지막 손순서이며 작성 시가 아니다.

| 판정 조건 | 아크션 |
|---|---|
| PR을 작성한다 | **`reviewers`·`--reviewer` 를 넘기지 않는다** ([guard-pr.sh](../../hooks/guard-pr.sh) 가 막는다) |
| 기표자 리뷰가 결착돼 Ready로 한다 | `update_pull_request` 의 **`draft:false` ＋ `reviewers` 를 1호출**로 보낸다 |
| Ready인 PR에 나중에 리뷰어를 더한다 | 그대로 설정해도 된다(막지 않는다) |

**누구를 설정하는가**: `design/` 의 변경이나 `DS-nn` 의 상태 갱신을 포함하면 **디자이너(지수)**. 판단이 갈리면 Hyeok을 더한다.

## 손순서 3: 올릴 때마다 저장된 본문을 확인한다

저장된 본문을 **가공하지 않는 경로**로 가져와 의도대로인지 확인한다.

| 경로 | 취급 |
|---|---|
| MCP `search_pull_requests` (`fields` 에 `body`) | 저장된 본문이 그대로 돌아온다. **확인은 이것을 쓴다** |
| `gh pr view --json body` | 같다 |
| MCP `pull_request_read` | **본문의 실체로 취급하지 않는다.** HTML 태그를 제거하고 `&` 를 `&amp;` 로 바꾼 가공판이 돌아온다 |

## 금지 사항

- 템플릿의 기입 지시를 이 스킬에 베끼는 것. 베끼면 한쪽만 갱신돼 어긋난다
- 맞춰보기(손순서 2)와 올린 뒤의 확인(손순서 3)을 생략하는 것
