# 1부 — UX 설계 의도 (§1~5) — 멘티와 다른 것

## 1. 화면의 사명

멘티와 같다. **더해지는 물음이 둘이다** — 「받은 신청에 내가 답했는가」(신청받은 멘토링) · 「받은 꽃송이가 얼마이고 정산됐는가」(정산).

## 2. 대상 사용자와 상황

- 대상 사용자: **로그인한 멘토.** 멘토도 다른 멘토에게 신청하므로 **신청한 멘토링** 탭이 따로 있다(2026-09-24 결정)
- 상황: ① 알림 「멘토링 신청이 도착했습니다」 → **신청받은 멘토링** ② 정산 알림 → **정산 수단 / 이력** ③ 아바타 → 멘토 프로필

## 3. 액션 방침

- 주 액션: **받은 신청에 답한다** — 수락(일정 제안) · 사양 · 재조정 · 참가 · 격려 메세지
- 부 액션: 정산 신청 · 계좌 변경 · 최소 금액 · 자동 기부 · 그 밖은 멘티와 같다

**하지 않는 것**에 더해지는 것: **프로필을 여기서 고치지 않는다** — 멘토 프로필은 `mentor-detail` 의 본인 면이 편집한다. 이 탭은 그리로 보낸다.

# 2부 — 구조 (§6~11) — 멘티와 다른 것

## 6. 블록별 규칙

### 세로 메뉴

**7항목**이고(로그아웃은 메뉴에 없다 · 새 판), 3번째 「나의 1:1 멘토링」이 **▼ 로 접힌다.** 펼치면 하위 2개(신청받은 · 신청한)가 들여쓰기로 선다. 하위가 선택되면 부모도 켜진 면이다.

### 멘토 프로필 탭

본문이 없다. 메뉴를 누르면 **`mentor-detail?me=1`(본인 면)으로 간다(같은 탭).** `template/` 는 `role=mentor&tab=profile` 에서 「멘토 프로필은 멘토 상세 페이지에서 편집합니다」 한 줄 ＋ `Button outline` 「멘토 프로필로」 를 낸다.

| 블록 | 규칙 |
|---|---|

| 상태 | 문구 | 버튼 |

### 수락 모달 — 일정 제안
