# DS-update-list.md — 디자인 시스템 갱신 요구

> 디자이너에서 구현으로 디자인 시스템 갱신 요구를 넘기는 **유일한 그릇**이다.
> **1요구 1행. `DS-nn` 은 재사용하지 않는다. 행은 삭제하지 않는다.**

## 방향 원칙

- 구현의 트렁크는 `packages/design-system` 이다. 컴포넌트의 형태(인라인 style 유지 / Tailwind 변환)는 S6에서 정한다.
- **Claude Design의 디자인 시스템 산출물은 이식원이다** — 토큰은 무손실 복사, 컴포넌트는 소스 이식한다(`docs/SOURCES.md` 「Claude Design 산출물」).
- **`template/`(Figma 비주얼 export)은 이식원이 아니다.** 시각적 참조이며 CSS를 옮기지 않는다.
- 요구는 전부 **디자인 시스템의 어휘(토큰·컴포지션)의 연장으로** 구현한다. 화면 단위의 일회성 예외를 만들지 않는다.
- 반영 순서는 **토큰 층 → 컴포넌트 층**이다. 토큰이 흔들리면 컴포넌트를 두 번 만지게 된다.

## 상태 기계

```
요구 ──→ 반영 ──→ 확인 ──→ 사인오프 ──→ 완료
 ↑                    │
 └──── 되돌림 ←────────┘
```

| 상태 | 누가 | 판정 조건 |
|---|---|---|
| **요구** | 디자이너 | 1행 기표된 시점 |
| **반영** | Claude Code | **Storybook에 올라간 시점.** 반영PR 난을 기입한다 |
| **확인** | 디자이너 | 로컬 `pnpm storybook` 으로 대조한 시점 |
| **사인오프** | 디자이너 | 상태 갱신 PR에 **Approve** 한 시점 |
| **완료** | — | 같은 PR에 사인오프 난(승인자·날짜)과 상태＝완료를 추기하고 머지한 시점 |

### 「반영」을 Storybook 등재로 고정하는 이유

구현 빌드의 행선지가 미정이다. **「앱에 반영되었는가」를 기준으로 잡으면 리포가 갈린 순간 이 상태 기계가 무너진다.** Storybook은 디자인 시스템에 붙어 있으므로 어디로 가든 따라간다.

### PR에서의 운용

- 구현 PR의 머지는 **사인오프를 기다리지 않는다.**
- 머지 후에 **상태 갱신 PR**(각 행 요구→반영·반영PR 기입)을 기표한다. 리뷰어는 디자이너다.
- 디자이너는 **로컬 Storybook** 으로 대조하고, 그 PR에 **Approve 하는 것이 사인오프**다.
- 지적은 **Request changes**(＝되돌림)로 반환한다.
- Approve 후, **같은 PR** 에 사인오프 난과 상태＝완료를 추기하고 머지한다. 1본의 PR에 기입과 사인오프가 남는다.

### 되돌림과 종단

- **되돌림**: 요구대로 만들 수 없다 / 정본 쪽의 상정이 틀렸다 → 상태를 「요구」로 되돌리고 무엇을·왜를 개정한다.
- **종단 상태** (전부 행을 남긴다):
  - **통합** — 중복이다. 종단 이유에 후계 ID를 적는다
  - **취하** — 불필요해졌다. 기안자가 닫는다
  - **각하** — 디자인 시스템의 범위 밖이다. 이유와 대체를 적는다

## 기표할 때의 규칙

| 판정 조건 | 아크션 |
|---|---|
| 화면 작업 중에 디자인 시스템에 없는 요소가 필요해졌다 | **화면에서 즉석으로 만들지 않는다.** 여기에 기표한다 |
| 대비·포커스 표시·타겟 사이즈의 미달을 발견했다 | 여기에 기표한다. 토큰·컴포넌트 층에서 한 번 정하면 전 화면에 먹는다 |
| 같은 요구가 이미 있다 | 새 행을 만들지 않는다. 기존 행을 개정한다 |
| 그 화면에서만 성립하는 판단이다 | 여기가 아니라 그 화면의 `UI-SPEC.md` §6에 쓴다 |
| 2화면 이상에서 성립하는 UX 판단이다 | 여기가 아니라 `UX-PATTERNS.md` 로 승격시킨다(`P-nn`) |

**「무엇을·왜」의 한 줄이 없는 행은 받지 않는다.** 근거가 없으면 나중에 재교섭할 수 없다(DESIGN-CHARTER 원칙 8).
