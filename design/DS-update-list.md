# DS-update-list.md — 디자인 시스템 갱신 요구

> 디자인 시스템 사양의 **미비·미정**을 담는 그릇이다. 사양 자체는 [`ds-export/`](ds-export/SOURCE.md) 가 갖는다.
> **1요구 1행. `DS-nn` 은 재사용하지 않는다. 행은 삭제하지 않는다.**

## 방향 원칙

- **정본에 축이 둘이다** — **편집은 Claude Design**, **참조는 [`design/ds-export/`](ds-export/SOURCE.md)**. 정의는 [docs/SOURCES.md](../docs/SOURCES.md) 「정본의 두 축」이다.
- **사양은 `ds-export/` 가, 미비·미정은 이 문서가 갖는다.** 여기에 토큰 값이나 치수를 적지 않는다(헌장 원칙 4).
- **컴포넌트의 형태(인라인 style 유지 / Tailwind 변환)는 엔지니어가 정한다.** 이 리포에서 정하지 않는다.
- **`template/`(Claude Design 화면 프로토타입의 export)은 이식원이 아니다.** 시각적 참조이며 CSS를 옮기지 않는다.
- 요구는 전부 **디자인 시스템의 어휘(토큰·컴포지션)의 연장으로** 구현한다. 화면 단위의 일회성 예외를 만들지 않는다.
- 반영 순서는 **토큰 층 → 컴포넌트 층**이다. 토큰이 흔들리면 컴포넌트를 두 번 만지게 된다.

## 상태 기계

```
요구 ──→ 반영 ──→ 완료
 ↑          │
 └─ 되돌림 ←┘
```

| 상태 | 누가 | 판정 조건 |
|---|---|---|
| **요구** | 디자이너 | 1행 기표된 시점 |
| **반영** | 디자이너 | **Claude Design 에 들어간 시점.** Claude Code 가 프롬프트를 쓰고 디자이너가 실행한다 |
| **완료** | 디자이너 | **재export 해서 `ds-export/` 를 교체한 PR 이 머지된 시점.** 교체PR 난과 완료일을 기입한다. **이 칸이 사인오프를 겸한다**(아래) |

### 「완료」를 export 교체로 고정하는 이유

**이 리포는 디자인 시스템을 구현하지 않는다**([ADR-0005](../docs/adr/0005-design-team-deliverables.md)). Storybook 이 없으므로 등재를 기준으로 삼을 수 없다.

`ds-export/` 는 **인계 산출물**이다. 여기에 들어오지 않은 것은 엔지니어에게 도달하지 않는다. 그래서 도달 시점을 완료로 잡는다.

### PR에서의 운용

- Claude Design 작업은 **디자이너가 한다.** AI 는 Claude Design 을 조작할 수 없다.
- 작업이 끝나면 **재export 하고 `ds-export/` 를 통째로 교체한다.** 부분 갱신을 하지 않는다.
- 같은 PR 에서 ① `ds-export/SOURCE.md` 의 SHA-256 ② 해당 행의 상태＝완료·교체PR·완료일을 갱신한다.
- **리뷰는 별 세션의 `/pr-review` 다.** diff 로 무엇이 바뀌었는지 대조한다.
- 요구대로 안 됐으면 상태를 **요구**로 되돌리고 「무엇을·왜」를 개정한다.

#### 사인오프는 「완료일」이 겸한다

**사인오프 칸을 따로 두지 않는다.** 완료 ＝ 교체 PR 이 머지된 시점이고, **그 PR 의 Approve 가 사인오프**다. 승인자는 PR 에 남는다.

| 판정 조건 | 아크션 |
|---|---|
| 누가 승인했는지 알고 싶다 | **교체PR 난의 PR 을 연다.** 표에 승인자를 복제하지 않는다 |
| DS 를 고친 사람과 승인할 사람이 같다 | **정상이다.** 실제 게이트는 **별 세션의 `/pr-review`** 다 |

칸을 되살리지 않는 이유는 **완료와 사인오프가 같은 시점**이기 때문이다. 두 칸에 같은 날짜를 적게 된다.

#### 제거 요구도 같은 상태 기계를 쓴다

**상태 기계는 「추가」 방향으로 읽히지만 제거도 같은 3단으로 돈다.** 방향이 반대라고 별도 상태를 만들지 않는다.

| 상태 | 추가일 때 | **제거일 때** |
|---|---|---|
| **요구** | 없는 것을 기표한다 | **지울 것을 기표한다** |
| **반영** | Claude Design 에 만들어졌다 | **Claude Design 에서 지워졌다** |
| **완료** | 재export 로 `ds-export/` 에 들어왔다 | **재export 로 `ds-export/` 에서 사라졌다** |

**완료의 판정은 양쪽 다 「`ds-export/` 가 그 상태인가」다.** 엔지니어에게 도달하는 것이 그것뿐이므로 기준이 하나로 유지된다.

#### 사양이 미정인 행은 착수 대상이 아니다

**상태가 `요구` 인 것에는 두 종류가 섞인다** — 만들 수 있는 것과 사양이 아직 없는 것이다. 상태만으로는 구별되지 않는다.

| 판정 조건 | 아크션 |
|---|---|
| 사양이 아직 정해지지 않았다 | **「무엇을·왜」에 「판정:」으로 무엇을 기다리는지 적는다.** 상태는 `요구` 그대로 둔다 |
| 「판정:」에 대기가 적혀 있다 | **⑥ DS 갱신에서 착수 대상으로 고르지 않는다.** 골라도 두 번 만들게 된다 |
| 대기가 풀렸다 | 「판정:」을 지우고 같은 PR 에 그 사실을 쓴다 |

상태를 하나 더 만들지 않는 이유는 **대기의 종류가 행마다 다르기 때문**이다. 상태로 만들면 「사양대기」·「자산대기」·「판정대기」가 계속 늘어난다.

### 되돌림과 종단

- **되돌림**: 요구대로 만들 수 없다 / 정본 쪽의 상정이 틀렸다 → 상태를 「요구」로 되돌리고 무엇을·왜를 개정한다.
- **종단 상태** (전부 행을 남긴다):
  - **통합** — 중복이다. 종단 이유에 후계 ID를 적는다
  - **취하** — 불필요해졌다. 기안자가 닫는다
  - **각하** — 디자인 시스템의 범위 밖이다. 이유와 대체를 적는다
