# 화면 인벤토리

> mentree 리뉴얼의 화면 목록과 진행 상태다. **어느 화면부터 만들지**를 여기서 정한다.
> **화면끼리 어떻게 이어지는지는 [transition-map.md](transition-map.md) 가 갖는다.**
> **as-is 조사는 하지 않는다**([ADR-0004](../../docs/adr/0004-no-as-is-survey.md)). 만들 대상은 와이어에서 나온다.
> 출처: Figma 「Mentree 2.0 (Claude)」 페이지(`1059:30246`).

| 판정 조건 | 아크션 |
|---|---|
| 화면 작업을 시작한다 | **그 화면의 section id 를 다시 읽는다.** 와이어는 계속 는다 |
| 섹션이 늘거나 줄었다 | **이 표를 갱신한다.** 그리고 무엇이 바뀌었는지 PR 본문에 쓴다 |
| 총 노드 수를 근거로 쓰고 싶다 | **쓰지 않는다.** 세는 방법이 갈려 재현되지 않는다 |

## 무엇을 1화면으로 세는가

**전이의 목적지가 되는 것이 1화면이다.** 화면 1장 ＝ `UI-SPEC.md` 1본 ＝ PR 1본이다.

| 판정 조건 | 아크션 |
|---|---|
| 로딩·빈 상태·에러다 | **화면이 아니다.** UI-SPEC **§7**(4상태)에 쓴다 |
| 같은 셸에서 탭·블록만 바뀐다 | **화면이 아니다.** UI-SPEC **§6**(블록별 규칙)에 쓴다 |
| 모달·시트·드롭다운이다 | **화면이 아니다.** 부모 화면의 §6·§7 에 쓴다. **단 아래 「모달인가 화면인가」를 먼저 통과시킨다** |
| 전이의 목적지가 된다 | **화면이다.** UI-SPEC **§9**(화면 전이)의 노드가 된다 |
| 여러 스텝을 순서대로 밟는다 | **1화면으로 센다.** 상태가 아니라 순서다(예: 회원가입 3스텝) |
| 역할(멘티·멘토)로 구성이 통째로 갈린다 | **2화면으로 센다.** 블록이 아니라 화면이 다르다 |

이 규칙으로 **19화면**이 나온다. 마이페이지가 가진 탭(멘티 9 ＋ 멘토 10)은 그 2화면의 §6 이다.

### 모달인가 화면인가

**와이어가 모달로 그려져 있다는 이유로 모달로 확정하지 않는다.** 1.0 이 모달이었던 것을 답습한 자리가 있다.

| 판정 조건 | 아크션 |
|---|---|
| **결제·환불이 걸린다** | **화면으로 만든다** |
| **입력 폼이 2스텝 이상이거나 장문(200자 초과)이다** | **화면으로 만든다** |
| 읽기 중심이고 **목록의 맥락을 유지해야** 한다 | **모달로 만든다** |
| 모달 안에서 비가역 조작이 필요하다 | **모달을 겹치지 않는다.** 같은 모달의 화면을 갈아끼운다 |

**근거는 결제다.** PG 사가 아직 미정인데(「착수 전 준비」의 결제 모듈), PG 는 리다이렉트·iframe·SDK 중 무엇을 강제할지가 제각각이다. **모달을 전제로 그려두면 PG 가 정해졌을 때 통째로 다시 그린다.** 거기에 새로고침·뒤로가기로 입력이 날아가는 문제가 겹친다.

이 판정으로 **`mentoring-apply` 는 화면**, **멘토링 상세는 모달**이 됐다(2026-09-10). 2화면째에 같은 판단이 나오면 [UX-PATTERNS](../UX-PATTERNS.md) 로 승격시킨다(헌장 원칙 7).

### 09-10 에 2화면이 모달로 내려갔다

**와이어의 레이어가 `modal_BG` 위에 얹혀 있다.** 화면이 아니라 부모 화면의 §6 이다.

| 없어진 screen-id | 어디로 | 무엇으로 |
|---|---|---|
| `mentoring-detail-mentee` | **`mypage-mentee` §6** | `MentoringDetailModal`(상태 6) |
| `mentoring-detail-mentor` | **`mypage-mentor` §6** | `MentoringDetailModal`(상태 6·액션이 다르다) |

**`mentoring-apply` 는 화면으로 남겼다.** 결제가 걸려 있어 위 「모달인가 화면인가」의 첫 행에 해당한다. 와이어는 모달로 그려져 있으나 그것은 1.0 의 답습이다.

**착수 전 준비도 함께 이사했다** — 「환불 규정」이 `mypage-mentee`·`mypage-mentor` 에 새로 붙었다. 없으면 취소 화면의 문구를 못 쓴다.

### 「착수 전 준비」의 어휘

| 말 | 무엇을 기다리는가 | 누가 |
|---|---|---|
| **환불 규정** | 과금·환불 규정 문서. 24시간 룰과 결제 수수료 3.4% 룰의 관계 | 사업 |
| **편집 모달 사양** | `mentor-detail` 「본인 프로필」의 편집 모달 4종. 와이어가 **「각각의 모달 구성은 아직 작성중」**이라고 스스로 적는다 | 디자이너 |
| **프로필 URL 재정** | 같은 섹션 안에서 **주석과 화면이 어긋난다** — 주석은 「프로필 URL변경하는 기능은 삭제 → 문의로 소화하기」인데 「프로필 URL 변경하기」 모달이 상세까지 그려져 있다. **미결로 두고 착수해도 된다** | 디자이너 |
| **참조** | **상용 패턴의 레퍼런스 3~5장.** Mobbin·실서비스 캡처 ([UX-PATTERNS.md](../UX-PATTERNS.md) 「참조원」) | 디자이너 |
| **결제 모듈** | PG 사와 그 UI 형태(리다이렉트·iframe·SDK). 와이어가 빈 상자다 | 사업·엔지니어 |
| **헤더 구성 재정** | 헤더 좌측이 2종이다 — shadcn 계통은 3메뉴, `mentor-detail` 은 검색창 ＋ 「멘토 전체보기」 ＋ 우하단 플로팅 벨. **UI 가 아니라 구성의 차이다** | 디자이너 |
| **알림 켜는 자리** | Q&A 의 「답변이 달리면 알림 받겠습니까」는 **토스트를 놓치면 안 받음으로 확정된다**(`DS-09`). 나중에 켤 자리가 없으면 놓치면 끝이다 | 디자이너 |
| **로그아웃 자리** | 아바타가 마이페이지 직행이라 메뉴가 없다. 「계정 설정」 안에 위계를 낮춰 놓기로 했으나 **와이어에 실물이 없다** | 디자이너 |
| **로그인 후 착지점** | 특정 액션 중에 가입했을 때 그 액션으로 돌려보낼지. **와이어가 물음표로 끝낸다** | 디자이너 |
| **와이어** | 와이어 자체가 없다 | 디자이너 |
| **AiBand 섹션 존치 판정** | Phase 진단이 MVP 밖이 되어 TOP 의 진입 배너를 남길지 정한다 | 디자이너 |

## 무게 — 일정의 분모

| 무게 | 화면 수 | 환산 | 어느 화면 |
|---|---|---|---|
| 가벼움 | 4 | ×0.5 ＝ 2 | |
| 보통 | **10** | ×1 ＝ 10 | |
| **무거움** | 2 | ×2.5 ＝ 5 | `mentor-detail` · `mentoring-apply` |
| **무거움 2배** | 2 | **×5 ＝ 10** | `mypage-mentee` · `mypage-mentor` |
| (와이어 없음) | 1 | 세지 않는다 | `event-detail` |

**표준화면 환산 약 27장이다.** 4장이 전체의 **절반 이상**을 차지한다.

> **09-02 에 25.5 에서 27 로 늘었다.** `mentor-detail` 을 보통에서 무거움으로 올렸다 — 13번째 섹션이 발견되면서 **「본인 프로필」 편집 모드와 편집 모달 4종**이 범위에 들어왔다.

> **09-10 에 화면이 21 에서 19 로 줄었으나 27 은 그대로다.** 모달로 내린 2화면의 일이 사라진 것이 아니라 부모가 안았다 — 그래서 `mypage-*` 에 **무거움 2배**를 신설했다. 2.5 ＋ 2.5 ＝ 5 로 정확히 가산된다. **일정은 바뀌지 않는다.**

## 만드는 순서

| 판정 조건 | 아크션 |
|---|---|
| 첫 화면을 고른다 | **파이프라인을 실증할 수 있는 작은 화면**을 고른다. 제일 중요한 화면을 고르지 않는다 |
| 디자인 시스템이 아직 얇다 | 부품을 적게 쓰는 화면부터 만든다. `DS-nn` 이 한꺼번에 쏟아지지 않게 한다 |
| 화면끼리 의존한다 | 전이의 출발점이 되는 화면을 먼저 만든다 |
| 사양 주석이 0이다 | **뒤로 미룬다.** 선례가 쌓인 뒤에 물어야 물을 것이 정해진다 |

### 권하는 차례

| 순 | 화면 | 왜 |
|---|---|---|
| 1 | `notice-list` · `notice-detail` | 가볍고 주석이 있다. **파이프라인 실증이 목적**이다 |
| 2 | `qna-feed` · `qna-detail` · `qna-compose` | 주석이 가장 두껍다. `P-nn` 이 여기서 쌓인다 |
| 3 | `insight-list` · `article-detail` | 목록·상세 패턴이 2에서 나온 것과 겹친다 |
| 4 | `mentor-search` · `mentor-detail` | 카드·필터가 DS 요구를 많이 낸다 |
| 5 | `login` · `password-reset` · `signup` · `onboarding-survey` | 플로우 단위로 묶인다 |
| 6 | `top` · `notification` | 주석이 0이다. 선례가 필요하다 |
| 7 | `mypage-mentee` · `mypage-mentor` · `mentoring-apply` | 무겁고 주석이 0이다. **마지막에 둔다** |
| — | `event-detail` | **와이어를 받은 뒤에 정한다** |

**「참조」가 필요한 것은 5번과 7번뿐이다.** 1~4·6 을 하는 동안에는 상용 패턴 레퍼런스를 모으지 않아도 된다.

### 실제 분담 — 이 차례를 앞지른다

**2026-09-11 에 2인이 동시에 착수했다.** 위 차례는 1인일 때의 기본값이고, 지금은 분담이 이긴다.

| 누가 | 순서 |
|---|---|
| **지수** | `top` → `mentor-search` → `mentor-detail` |
| **혁** | `qna-feed` → `qna-detail` → `qna-compose` |

| 판정 조건 | 아크션 |
|---|---|
| 분담과 위 차례가 어긋난다 | **분담이 이긴다.** 차례는 「누가 무엇을」이 없을 때의 기본값이다 |
| **파이프라인 실증**(`SETUP.md` §5)을 누가 하나 | **먼저 끝나는 1장이 겸한다.** `notice-list` 를 위해 따로 1장을 더 만들지 않는다 |
| 두 사람이 같은 표를 고친다 | `DS-update-list`·`UX-PATTERNS`·`screen-inventory` **3개뿐이다.** 손으로 병합하지 않는다(`SETUP.md` §6) |
