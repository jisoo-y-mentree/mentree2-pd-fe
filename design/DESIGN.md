> 이 문서에 규칙을 더하는 PR은 [DESIGN-CHARTER.md](DESIGN-CHARTER.md) 의 8원칙 테스트를 통과해야 한다.

## 쓰는 것 / 쓰지 않는 것

| 판정 조건 | 아크션 |
|---|---|
| 요소 하나의 규칙이고, 2화면 이상에서 실증되었다 | **여기에 쓴다** |
| 1화면에서만 성립한다 | 그 화면의 `UI-SPEC.md` §6에 쓴다 |
| 화면을 넘는 **UX 판단**이다(요소가 아니라 흐름) | [UX-PATTERNS.md](UX-PATTERNS.md) 에 `P-nn` 으로 쓴다 |
| 디자인 시스템의 구현이 필요하다 | [DS-update-list.md](DS-update-list.md) 에 `DS-nn` 으로 기표한다 |
| shadcn·Tailwind 의 일반 지식이다 | **쓰지 않는다**(헌장 원칙 6) |
| 실측값(색·치수)이다 | **쓰지 않는다.** 정본은 토큰이다. 의미와 규칙만 쓴다(헌장 원칙 4) |

**규칙마다 집행층을 적는다** — `[lint]` / `[review]` / `[signoff]` (헌장 원칙 5).
**규칙마다 근거를 한 줄 적는다** (헌장 원칙 8).

> **값을 찾는 사람에게**: 이 문서에 숫자가 없는 것은 의도다. 값의 정본은 [`ds-export/project/tokens/`](ds-export/project/tokens/) 다.

## 1. 색

**2계열로만 칠한다 — 중립은 sage, 브랜드는 green.** 세 번째 계열을 만들지 않는다.

| 판정 조건 | 아크션 |
|---|---|
| 텍스트·경계·입력·muted 표면이다 | **sage 계열**을 쓴다 |
| 프라이머리 버튼·활성 항목·차트·브랜드 강조다 | **green**(`--primary`)을 쓴다. `--accent` 도 같은 green 이다 |
| 화면 배경이다 | **white**(`--background`) 다. `sage-50` 은 **Hero·WorldMap 두 섹션의 포인트로만** |
| 기업 서비스(Biz)의 진입점·밴드다 | **`--biz-*` 만** 쓴다 |
| 본체의 `primary`·`accent`·`chart` 다 | **파랑을 섞지 않는다** |
| AI 관련 CTA·밴드다 | **sage/green 시맨틱 토큰으로만.** 보라·틴트 그라데이션을 쓰지 않는다 |
| 값을 직접 적고 싶다 | **hex 를 쓰지 않는다.** 시맨틱 토큰 또는 노출된 raw 스케일(`--sage-*`)을 쓴다 |

`[review]` — **lint 승격 후보**. `template/` 의 raw hex 는 기계로 잡을 수 있다.
**근거**: Biz 파랑이 본체에 섞이면 브랜드가 둘이 된다. AI 의 관용 팔레트(보라·틴트)를 허용하면 sage/green 체계 밖의 색이 화면마다 들어온다.

## 2. 타이포그래피

**Pretendard JP Variable 하나만 쓴다.**

| 판정 조건 | 아크션 |
|---|---|
| 폰트를 고른다 | **Pretendard JP Variable.** Inter · DM Sans · Nunito 를 쓰지 않는다 |
| 제목·본문의 크기를 고른다 | `display` · `h0` · `h1` · `h2` · `h3` · `body` · `caption` **7단 안에서** 고른다. 중간값을 만들지 않는다 |
| 숫자·카운터·금액이다 | **`.tabular` 를 붙인다** |
| 라벨·제목의 케이싱이다 | **문장형.** 전부 대문자를 쓰지 않는다. 라틴 약어는 그대로 둔다 |

`[review]`
**근거**: 한국어 우선에 일본어·라틴 폴백이라 **CJK 글리프 안정성**이 폰트 선택의 기준이다. 숫자가 tabular 가 아니면 목록에서 열이 흔들린다.

## 3. 조판과 금칙

**`word-break: break-all` 을 쓰지 않는다.**

| 판정 조건 | 아크션 |
|---|---|
| 텍스트가 컨테이너를 넘친다 | **`word-break: keep-all` ＋ `overflow-wrap: break-word`.** `tokens/base.css` 가 전역으로 강제한다 |
| 개별 요소에서 줄바꿈을 바꾸고 싶다 | **전역 설정을 덮어쓰지 않는다.** 넘치면 말줄임이나 레이아웃으로 푼다 |

`[review]`
**근거**: 제품이 **한/일 이중언어**다. `break-all` 은 어절 한가운데를 자른다. `keep-all` 이 어절을 지키고 `break-word` 가 넘침의 안전망이 된다.

## 4. 여백과 그리드

| 판정 조건 | 아크션 |
|---|---|
| 여백을 고른다 | **`--space-*` 스케일 안에서** 고른다. 중간값을 만들지 않는다 |
| 콘텐츠의 최대 폭이다 | `--container-max`. 좌우 패딩은 `--container-pad`(모바일에서 줄어든다) |
| 섹션 배경을 칠한다 | **배경은 풀블리드, 콘텐츠만 컨테이너에 정렬**한다 |

`[review]`
**근거**: 헤더·본문·푸터가 같은 컨테이너를 참조해야 **좌우 끝선이 맞는다.**

## 5. radius

| 판정 조건 | 아크션 |
|---|---|
| radius 를 고른다 | **`--radius-sm`·`md`·`lg`·`xl`·`2xl` 5단 안에서** 고른다 |
| 스케일의 값을 바꾸고 싶다 | **원시 radius 스케일을 수정하지 않는다.** 조정은 카드군 인스턴스 토큰에서 한다(§7) |
| 새 radius 가 필요하다 | **만들지 않는다.** `DS-nn` 으로 기표한다 |

`[review]` · 스케일 자체의 변경은 `[signoff]`
**근거**: 5단 밖의 값을 한 번 허용하면 화면마다 늘어난다. **대형 카드(bento grid)의 radius 는 아직 미정이다**(`DS-03`).

## 6. 표면 언어

### 6.1 카드인가 투명 컨테이너인가 — 2단으로 판별한다

| 판정 조건 | 아크션 |
|---|---|
| **인물·엔티티가 주인공**이다 ／ **액션(북마크·저장)이 붙는 객체**다 | **카드다**(흰 표면 ＋ 테두리 ＋ 그림자). 예: `MentorCard` · `InterviewCard` |
| 그 밖의 콘텐츠 프리뷰이고 **자체 미디어가 시각 경계를 만든다** | **투명 컨테이너다.** 예: `ArticlePreview` |
| 그 밖의 콘텐츠 프리뷰이고 **미디어 없이 텍스트 중심**이다 | **카드다.** 경계를 테두리로 부여한다. 예: `QnaCard` |

`[review]`
**근거**: 콘텐츠 종류가 늘어도 같은 판별을 쓸 수 있어야 한다. 「무엇처럼 보이는가」가 아니라 **경계를 무엇이 만드는가**로 가른다.

### 6.2 경계·리프트·포커스

| 판정 조건 | 아크션 |
|---|---|
| 구조를 나타낸다 | **경계(`--border` 헤어라인)** 로 한다 |
| 떠 있음을 나타낸다 | **그림자**로 한다. `xs`→`lg` 4단 |
| 투명 컨테이너의 hover 다 | **배경 틴트가 아니라** 경계를 가진 미디어 요소에 **그림자만** 얹는다. 위치 이동·확대를 하지 않는다 |
| 카드의 hover 다 | **그림자만 상승**한다. 이동하지 않는다 |
| 포커스를 나타낸다 | **`--ring`**(sage) 아웃라인. **green 을 쓰지 않는다** |
| 오버레이 뒤를 덮는다 | `sage-950` 저알파 스크림 ＋ 옵션 블러. **글래스모피즘이 아니다** |
| 움직임을 넣는다 | 짧은 ease 로 절제한다. **바운스·무한 루프를 쓰지 않는다** |

`[review]`
**근거**: 구조와 리프트를 같은 수단으로 나타내면 위계가 읽히지 않는다. 포커스가 green 이면 **브랜드 강조와 구별되지 않는다** — 포커스는 크롬으로 읽혀야 한다.

## 7. 카드 지오메트리 — 동심원 중첩

**바깥 radius ＝ 안쪽 radius ＋ 사이 간격.** 이 관계 하나가 규칙이다.

| 판정 조건 | 아크션 |
|---|---|
| 요소를 다른 면 위에 중첩한다 | **위 관계를 지킨다.** 카드뿐 아니라 **요소–싸개–컨테이너 전부**에 적용한다 |
| 면 위에 오버레이를 얹는다 | 오버레이의 radius 를 **그 면의 radius 에 맞춘다** |
| 미디어 위에 토글·버튼을 올린다 | **받침을 깐다** — 반투명 흰 면 ＋ `--shadow-sm` ＋ 헤어라인, radius 는 `--radius-md`. **정본은 `MentorCard` 우상단의 스크랩이다.** 새 오버레이는 그것을 복제하고 값을 다시 고르지 않는다 |
| 카드의 치수를 조정하고 싶다 | **카드군 인스턴스 토큰**(`--card-*`)에서 한다. 원시 radius 스케일을 건드리지 않는다 |

**미디어 위 오버레이의 정본이 바뀌었다**(2026-09-11). 전에는 `IconButton` default 를 썼다. 스크랩이 `CountToggle` 로 통일되면서 그 부품은 **배경이 없어졌고**, 사진 위에서 묻히지 않으려면 받침이 필요해졌다.

| 판정 조건 | 아크션 |
|---|---|
| 미디어 위 오버레이를 새로 단다 | **`MentorCard` 를 열어 그 받침을 그대로 가져온다.** 값을 새로 고르지 않는다 |
| 받침의 값을 바꾸고 싶다 | **`MentorCard` 에서 바꾼다.** 거기가 정본이다 |
| 배경을 채우는 반전으로 되돌리고 싶다 | **되돌리지 않는다.** 목록에 깔리면 반전 덩어리가 화면을 덮는다(§8 · `CountToggle` 의 예외) |

`[review]`
**근거**: 관계만 지키면 **값을 함께 조정할 수 있다.** 값을 개별로 고르면 중첩이 어긋나고 되돌릴 기준이 없어진다. **오버레이의 받침도 같다** — 카드마다 고르면 카드마다 달라진다.

## 8. 상태 표현

| 판정 조건 | 아크션 |
|---|---|
| 상태를 나타낸다 | **색만으로 나타내지 않는다.** 라벨·아이콘·형태를 함께 쓴다(WCAG 1.4.1) |
| Toggle 계열(`FilterChip`·`BookmarkToggle`)의 선택 상태다 | **반전**으로 나타낸다. 옅은 틴트로 끝내지 않는다 |
| 표시이면서 누를 수 있다 | **누를 수 있음이 형태로 드러나야 한다.** 카운터를 텍스트로만 두지 않는다 |
| 대비·포커스 표시·타겟 사이즈의 미달을 발견했다 | **화면에서 고치지 않는다.** `DS-nn` 으로 기표한다 |

`[review]`
**근거**: 이 리포에 **a11y 자동 검사가 없다**([ADR-0005](../docs/adr/0005-design-team-deliverables.md)). 색만으로 나타낸 상태는 기계도 사람도 못 잡는다.

## 9. 아이콘

| 판정 조건 | 아크션 |
|---|---|
| 아이콘을 쓴다 | **HugeIcons 만.** Lucide · Heroicons · 이모지 · 유니코드 아이콘을 쓰지 않는다 |
| 색을 바꾼다 | `.hgi` CSS 마스크로 **`currentColor` 를 따르게** 한다. 정적 SVG 의 하드코딩 stroke 를 그대로 두지 않는다 |
| 헤더·진입의 28px 컬러 SVG 다 | **예외다.** 현재는 provisional 이며 확정 자산을 기다린다(`DS-05`). **canon 으로 쓰지 않는다** |

`[review]` — **lint 승격 후보**. 다른 아이콘 세트의 import 는 기계로 잡을 수 있다.
**근거**: 와이어에 **6계통이 섞여 있다**([component-coverage](docs/component-coverage.md)). 한 세트로 모으지 않으면 획 굵기와 광학 크기가 화면마다 다르다.

## 10. 반응형

**3구간이다.** 구간의 정본은 [`ds-export/project/guidelines/03-responsive.md`](ds-export/project/guidelines/03-responsive.md) 다. 여기에 복제하지 않는다.

| 판정 조건 | 아크션 |
|---|---|
| 화면을 만든다 | **Desktop L / Desktop S / Mobile 3구간**을 전부 확인한다 |
| `template/` 을 낸다 | **CSS 가 3구간을 처리한다.** 구간마다 파일을 늘리지 않는다([ADR-0005](../docs/adr/0005-design-team-deliverables.md)) |
| 구간을 늘리고 싶다 | **늘리지 않는다.** `DS-nn` 으로 기표한다 |

`[review]`
**근거**: 구간이 늘면 화면 1장의 확인 비용이 그만큼 는다. 3구간이 이미 정해져 있다.

## 11. 브랜드와 로고

| 판정 조건 | 아크션 |
|---|---|
| 로고를 놓는다 | **3버전 중에서 고른다** — on white · on card · reversed on primary. 새 버전을 만들지 않는다 |
| 로고의 색이다 | `--brand-ink` 가 canon 이다 |
| 워드마크를 변형하고 싶다 | **변형하지 않는다** |

`[review]` · 자산 자체의 변경은 `[signoff]`
**근거**: 로고는 배경에 따라 버전이 갈린다. 그때그때 색을 바꾸면 세 버전의 의미가 없어진다.

## 12. 데이터인가 행동인가 — `Badge` · `Chip` · `Button`

**2층으로 판별한다.**

### 12.1 1층 — 무엇을 나타내나

| 판정 조건 | 아크션 |
|---|---|
| **데이터**를 나타내고 **안 눌린다** | **`Badge`**. 예: 국가 태그 · 키워드 태그 · 상태 |
| **데이터**를 나타내고 **눌린다** | **칩 계열**(아래 12.2). 예: 해시태그 · 필터 조건 |
| **행동**을 나타낸다 | **`Button`**. 예: 「이 멘토의 다른 답변 보기」 · 「감사인사 보내기」 |

**세 가지 신호로 데이터와 행동을 가른다.**

| | 데이터(칩) | 행동(버튼) |
|---|---|---|
| **라벨의 품사** | **명사** — 「일본취업」·「한국」 | **동사구** — 「다른 답변 보기」 |
| **서는 법** | **여럿이 세트로.** 서로 동격 | **단독** |
| **위계** | **없다** | **있다**(primary·secondary·ghost) |

| 판정 조건 | 아크션 |
|---|---|
| 「누르면 무엇이 일어나는가」로 가르고 싶다 | **가르지 않는다. 기준이 아니다.** 칩도 이동하고(해시태그) 버튼도 모달을 연다(멘토링 신청) |
| 라벨이 명사인데 단독으로 선다 | **버튼을 의심한다.** 셋 중 둘 이상이 맞아야 칩이다 |

### 12.2 2층 — 칩 안에서

| 판정 조건 | 아크션 |
|---|---|
| **상태를 갖는다**(켜짐/꺼짐) | **`FilterChip`**. 선택 시 green 반전 |
| **상태가 없다**(이동·제거·표시) | **`Chip`**. `--muted` 채움 · 아웃라인 없음 |

`[review]`
**근거**: 「상태 유무」만으로는 `Chip` 과 `Button` 이 안 갈린다 — 버튼도 상태가 없다. **1층에서 데이터와 행동을 먼저 가르지 않으면 같은 판단이 계속 뒤집힌다.** 실제로 `AnswerCard` 의 「이 멘토의 다른 답변 보기」가 뱃지→링크→칩→버튼으로 세 번 뒤집혔다(2026-09-11).

## 아직 여기에 없는 것

**화면에서 실증되면 올라온다**(헌장 원칙 7). 지금은 파운데이션만 있다.
